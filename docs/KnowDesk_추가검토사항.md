# Part B. DRM 대응 방안 상세

## B-1. 문제 정의

증권사 환경에서 유통되는 대부분의 업무 문서에는 문서보안(DRM)이 적용된다. DRM 적용 문서는 파일 자체가 암호화되어 있어, 인가되지 않은 프로세스가 열면 암호화된 바이너리만 읽히거나 접근이 차단된다.

이는 KnowDesk의 핵심 가치인 **본문 검색(Full Text Search)** 을 직접적으로 무력화한다.

> DRM 대응 방식의 결정은 본 제품의 실질적 효용을 좌우하는 최상위 의사결정 항목이다.

## B-2. 대응 옵션

### Option A. 예외 프로세스 등록 (Trusted Process Whitelisting)

DRM 클라이언트 에이전트에 KnowDesk 실행 파일을 인가 프로세스로 등록하여, 파일 접근 시 복호화된 스트림을 전달받는 방식.

- 애플리케이션 코드 수정 없이 기존 파서를 그대로 사용할 수 있다
- 실행 파일 코드사이닝 및 해시 등록이 필요하다
- 정보보호팀 승인 절차에 상당한 기간이 소요될 수 있다
- 실행 파일 갱신 시마다 재등록 절차가 필요하다

### Option B. DRM 벤더 복호화 API/SDK 연동

벤더가 제공하는 검색엔진·DLP 연동용 인터페이스를 통해 본문을 추출하는 방식.

- 사용자 권한 검증이 벤더 로직에 위임되어 보안 통제 관점의 정합성이 높다
- 별도 라이선스 비용이 발생할 수 있다
- 제품·버전별 지원 범위가 상이하므로 벤더 직접 확인이 필요하다
- 채택 시 PRD 5장 Out of Scope의 `사내 시스템 연계` 항목 수정이 필요하다

### Option C. 계층적 색인 (Graceful Degradation)

DRM 문서는 본문 색인을 포기하고 메타데이터만 색인하는 방식.

- 승인 절차 없이 즉시 적용 가능하다
- 파일명·경로·수정일 기반 탐색만 지원되므로 검색 품질이 제한된다
- **MVP 기본 정책으로 채택한다**
- A 또는 B 승인 이후에도 예외 파일 처리 경로로 유지한다

### Option D. 반출 문서 전용 폴더 운영

정식 반출 승인을 거쳐 평문화된 문서만 지정 폴더에 보관하고 해당 폴더를 색인하는 방식.

- 구현 난이도가 가장 낮다
- 사용자 수작업이 필요하여 문서 커버리지가 낮다
- 보조 수단으로만 활용한다

### 옵션 비교

| 구분 | A. 예외 프로세스 | B. 벤더 API | C. 계층적 색인 | D. 반출 폴더 |
|------|------------------|-------------|----------------|--------------|
| 본문 검색 | 가능 | 가능 | 불가 | 부분 가능 |
| 개발 난이도 | 낮음 | 중간 | 낮음 | 낮음 |
| 승인 난이도 | 높음 | 중간 | 없음 | 낮음 |
| 소요 기간 | 장기 | 중기 | 즉시 | 즉시 |
| 비용 | 없음 | 발생 가능 | 없음 | 없음 |
| MVP 적용 | 미적용 | 미적용 | **적용** | 선택 적용 |

## B-3. 계층적 색인 정책 (MVP 적용 상세)

| 계층 | 대상 | 색인 범위 | 검색 결과 표시 |
|------|------|-----------|----------------|
| Full Index | 비DRM 문서 | 파일명 + 본문 + 메타데이터 | 본문 미리보기 제공 |
| Meta Index | DRM 적용 문서 | 파일명 + 경로 + 수정일 + 크기 + 확장자 | `본문 미색인(보안 문서)` 배지 |
| Skip | 손상·암호 설정·미지원 포맷 | 색인 제외 | 미표시 (실패 로그만 기록) |

처리 규칙:

- 본문 추출 실패 시 오류로 처리하지 않고 Meta Index 계층으로 자동 강등한다
- 강등 사유(DRM / 손상 / 암호 / 파싱 실패)를 구분하여 기록한다
- 색인 요약 정보를 제공한다. 예: `전체 1,240건 중 본문 색인 890건, 메타 색인 310건(DRM), 실패 40건`
- 향후 DRM 해소 시 Meta Index 문서만 선별 재색인할 수 있도록 상태값을 보관한다

## B-4. Phase 2 전환 대비 설계 요구사항

구조 변경을 최소화하기 위해 MVP 단계에서 다음을 준수한다.

- 본문 추출 모듈을 **인터페이스로 추상화**하여 추출 방식 교체가 가능하도록 구성
- 문서별 색인 계층·강등 사유·최종 시도 일시를 스키마에 포함
- 재색인 대상을 선별 조회할 수 있는 쿼리 경로 확보

# Part D. 구현 착수 전 확정 필요 사항

> 아래 D-1~D-4는 **나중에 변경하면 색인 전체를 재생성해야 하는 항목**이다.
> 설계 단계에서 우선 확정한다.

## D-1. 데이터 모델 및 상태 전이 `우선순위 1`

### 확정 필요 항목

- **문서 고유 식별자 기준** — 파일 경로 기준인가, 내용 해시 기준인가
  - 경로 기준: 파일 이동 시 별개 문서로 인식됨
  - 해시 기준: 동일 내용 사본이 하나로 병합됨. F-06(최신 버전 탐지)과 직결
- **상태 전이 정의** — `발견 → 대기 → 추출 중 → 색인 완료 / 강등 / 실패 → 재색인 필요 → 삭제됨`
- **실패 재시도 정책** — 재시도 횟수, 간격, 영구 포기 조건
- **동시성 처리** — 색인 도중 파일이 수정된 경우, 색인 도중 프로세스가 강제 종료된 경우
- **네트워크 드라이브 오프라인 처리** — 삭제로 간주할 것인가 보류할 것인가
  - 삭제로 처리 시, VPN 연결이 끊길 때마다 색인이 소실되는 문제 발생

## D-2. 검색 결과 랭킹 규칙 `우선순위 2`

검색 품질에 대한 사용자 불만은 대부분 이 영역에서 발생한다.

- 파일명 일치와 본문 일치의 가중치 비율
- 수정일 최신성 가중치 — 3년 전 문서와 지난주 문서의 점수 차이
- 다중 키워드 처리 — AND / OR / 근접도(proximity)
- Meta Index 문서를 Full Index 문서와 동일 목록에 혼합할 것인가, 분리 표시할 것인가
- 검색 결과 0건 시 동작 — 오타 교정 제안, 조건 완화 재검색 여부

## D-3. 한국어 처리 세부 규칙 `우선순위 3`

- **형태소 분석기 적용 여부** — 미적용 시 `발행절차`를 `발행`으로 검색 불가
- 영문 대소문자, 전각·반각 정규화
- 공백 없는 복합어 처리
- 숫자·특수문자 포함 토큰 (`ELS-2024`, `v1.2`)
- **사내 약어 동의어 사전** — 사용자 등록 기능 제공 여부

## D-4. 마이그레이션 및 버전 관리 `우선순위 4`

개인 PC 설치형에서 자주 누락되며, 2차 릴리스에서 반드시 문제가 된다.

- 앱 업데이트 시 기존 색인 DB 유지 여부, 전체 재색인 필요 여부
- 색인 DB 스키마 변경 시 마이그레이션 경로
- 색인 DB 손상 감지 및 복구 절차
- 설정 백업, PC 교체 시 이전 방법
- 배포 방식 — 사내 SW 배포 시스템 활용 여부, 설치 시 관리자 권한 필요 여부

# Part E. 구현 병행 확정 가능 사항

> D와 달리 구현과 병행해 정해도 손실이 적은 항목이다.

## E-1. 설정 항목 명세

설정 화면은 구현 중 항목이 늘어나기 쉬운 영역이므로 사전 확정을 권장한다.

- 색인 대상 폴더 추가·제외
- **제외 패턴** — 확장자, 파일명 규칙, 임시파일(`~$`), 백업 폴더, 대용량 아카이브
- 색인 수행 시간대 및 리소스 상한
- 전역 단축키 변경
- 검색 결과 표시 개수
- 시작 시 자동 실행 여부
- 색인 DB 저장 위치
- 색인 초기화

> 제외 패턴이 없으면 임시파일·백업본이 색인되어 검색 품질과 성능이 동시에 저하된다.

## E-2. 온보딩 첫 경험

설치 직후는 초기 색인이 완료되기 전이므로 검색이 사실상 동작하지 않는다. 제품 이탈이 가장 많이 발생하는 구간이다.

- 최초 실행 시 폴더 등록 유도 흐름
- 초기 색인 진행률 및 **예상 소요 시간 안내**
- 색인 미완료 상태에서 검색 시 안내 문구
- 대상 문서가 과다할 때 경고 및 범위 축소 제안

## E-3. 관측 가능성 (Observability)

로컬 설치형은 문제 재현이 어렵다. 진단 수단을 초기부터 포함하지 않으면 사용자 지원이 불가능해진다.

- 로그 레벨, 보관 기간, 최대 용량, 순환 정책
- 사용자가 진단 정보를 파일로 내보내는 기능
- 색인 통계 화면 — 대상·완료·실패·강등 건수, 소요 시간
- **로그 마스킹 규칙** — 문서 본문 및 검색어가 로그에 기록되지 않도록 처리 (보안 검토 대상)

## E-4. 오류 메시지 및 사용자 안내 문구

실패 경로별 문구를 사전 확정하여 품질 편차를 방지한다.

| 상황 | 안내 필요 내용 |
|------|----------------|
| 권한 없음 | 접근 불가 사유, 관리자 문의 안내 |
| 파일 잠김 | 다른 프로그램에서 사용 중임을 안내 |
| 원본 삭제됨 | 색인은 존재하나 파일이 없음을 안내 |
| 드라이브 오프라인 | 네트워크 연결 확인 안내, 색인 보존 여부 명시 |
| 색인 DB 손상 | 복구 또는 재색인 선택지 제공 |
| 디스크 공간 부족 | 필요 용량 및 정리 방법 안내 |

## E-5. 비기능 요구사항 측정 조건

`검색 1초 이내`, `CPU 1% 미만` 등의 수치는 측정 조건이 없으면 검증할 수 없다.

- 기준 하드웨어 사양 — 사내 표준 PC 스펙 명시
- 기준 데이터셋 — 문서 건수 및 총 용량
- 측정 구간 정의 — 검색 응답이 첫 결과 표시 시점인가, 전체 렌더링 완료 시점인가
- 통계 기준 — 평균인가 P95인가

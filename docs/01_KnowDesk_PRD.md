# 1. 목표 (Goal)

## 해결하는 문제

증권사 임직원은 업무 매뉴얼, 규정집, 리서치 자료, 상품 검토 문서, 회의자료 등 수천 건의 문서를 지속적으로 생산·활용한다.

문서가 누적될수록 다음 문제가 발생한다.

- 문서를 저장한 위치를 기억하기 어렵다.
- Windows 파일 검색만으로는 본문 검색이 제한적이다.
- 동일 문서의 여러 버전 중 최신본을 찾기 어렵다.
- 과거 업무 산출물을 재활용하기 어렵다.

---

## 해결 방향

KnowDesk는 사용자가 지정한 폴더를 자동으로 색인하고, 전역 단축키로 언제든지 호출 가능한 검색 창을 통해 문서를 즉시 탐색할 수 있는 로컬 검색 플랫폼이다.

제품은 다음 원칙을 따른다.

- 인터넷 연결 없이 동작
- 외부 API 없이 동작
- 개인 PC 내 로컬 실행
- DRM 정책 우회 금지

---

## 기대 효과

- 문서 탐색 시간 감소
- 과거 지식 재사용 증가
- 개인 생산성 향상
- 중복 작업 감소

## 원문 저장 정책 (v1.1 개정 — 상세 근거는 `11_Implementation_Plan.md` 참조)

저장 허용

- 추출된 원문 본문
- 형태소 토큰 (평문)
- 역색인 정보
- 메타데이터

저장 금지

- 스니펫 캐시 (검색 시 DB에 저장된 원문에서 즉시 생성하며, 별도 캐시 테이블에 영속화하지 않는다)
- 요약

변경 사유

- HMAC 기반 비가역 토큰 저장 방침을 폐기한다. HMAC을 적용하면 Prefix 검색(`발행*`)과 하이라이트가 원리적으로 불가능해지고, 검색 품질을 조정할 때마다 전체 문서를 재추출해야 하는 비용이 더 크다고 판단했다.
- 원문 저장 여부는 저장 계층 추상화(`DocumentStore`)로 감싸, 필요 시 압축 저장으로 전환할 수 있게 설계한다.
- DB 암호화 적용 여부는 O-5(색인 DB 사전 검토) 확인 후 결정한다. 확정 전까지는 미적용 상태로 개발한다.

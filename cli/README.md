# kdfind

폴더 하나와 검색어를 주면 그 자리에서 훑어 검색해주는 도구다. 색인 파일을 미리 만들 필요가 없고, 실행이 끝나면 아무것도 디스크에 남기지 않는다 — 매번 그 폴더를 다시 훑는다.

> 이 저장소에는 `knowdesk-cli`(`index`/`search`/`stats`/`watch`/`bench` 서브커맨드가 있는 개발용 헤드리스 검증 도구)도 있다. `kdfind`는 그것과 다른, 단독 배포용 별도 도구다.

---

## 사용법

```
kdfind <폴더> [검색어...] [-f] [-l N]
```

| 인자 | 설명 |
|---|---|
| `<폴더>` | 검색할 폴더 (필수) |
| `[검색어...]` | 검색창에 타이핑하듯 그대로 입력. 여러 단어로 나눠 써도 다시 하나로 합쳐진다 |
| `-f`, `--filename` | 있으면 파일명 검색 모드 (없으면 기본: 내용 검색) |
| `-l N`, `--limit N` | 결과 개수 상한. 기본 `0` = 무제한 |

**`-f`/`-l`은 검색어보다 앞에 쓴다.** 검색어가 시작되면 그 뒤에 오는 건 `-f`/`-l`이 나와도 전부 검색어의 일부로 취급된다.

### 예시

```bash
# 기본 키워드 검색
kdfind ./문서모음 채권

# AND/OR/NOT은 따옴표 없이 그냥 단어로 쓰면 된다
kdfind ./문서모음 채권 AND 발행

# 구(phrase) 검색은 큰따옴표가 필요한데, 셸이 그 따옴표를 먹어버리므로
# 작은따옴표로 한 번 더 감싸서 큰따옴표가 그대로 전달되게 한다
kdfind ./문서모음 '"채권 발행"'

# 파일명 모드, 결과 5건만
kdfind ./문서모음 -f -l 5 보고서
```

## 검색 문법

내용 검색(기본 모드):

- `채권 발행` — 두 단어 모두 포함
- `채권 OR 회사채` — 둘 중 하나라도 포함
- `채권 NOT 국채` — 앞 단어는 포함, 뒷 단어는 제외
- `(채권 OR 회사채) AND 발행` — 괄호로 우선순위 지정
- `"채권 발행"` — 띄어쓰기까지 정확히 일치하는 구문만 (셸 따옴표 처리는 위 예시 참조)
- `발행*` — "발행"으로 시작하는 모든 단어

필터(내용·파일명 검색 모두 적용, 검색어와 함께 그냥 입력):

- `x:pdf` — 확장자로 좁히기
- `p:리서치` — 경로에 이 문자열이 포함된 문서만
- `m>2026-01-01` / `m<2026-08-01` / `m=2026-08-10` — 수정일 이후/이전/정확히 일치

파일명 모드(`-f`)에서는 위 연산자·구·와일드카드가 전부 무시되고, 띄어쓰기로 나눈 각 단어가 파일명에 부분 문자열로 포함되는지만(전부 만족해야 함) 본다. 필터는 파일명 모드에서도 동일하게 동작한다.

지원 문서 형식: Word(`.docx`), Excel(`.xlsx`), PowerPoint(`.pptx`), PDF, 일반 텍스트(`.txt`), 마크다운(`.md`).

## 설정 파일 `settings_cli.json`

**`kdfind`는 환경변수를 전혀 읽지 않는다.** 형태소 분석기(Kiwi)·PDF 추출기(PDFium) 경로는 전부 이 설정 파일에서만 읽는다. 처음 실행하면 아래 기본값으로 자동 생성된다.

| OS | 경로 |
|---|---|
| Linux | `~/.local/share/KnowDesk/settings_cli.json` |
| macOS | `~/Library/Application Support/KnowDesk/settings_cli.json` |
| Windows | `%LOCALAPPDATA%\KnowDesk\settings_cli.json` |

```json
{
  "enable_morphological_analysis": false,
  "kiwi_lib_path": null,
  "kiwi_model_dir": null,
  "pdfium_lib_dir": null
}
```

| 필드 | 기본값 | 설명 |
|---|---|---|
| `enable_morphological_analysis` | `false` | 형태소 분석기(Kiwi)를 켤지 여부. 켜려면 아래 두 경로도 함께 채워야 한다. |
| `kiwi_lib_path` | `null` | Kiwi 네이티브 라이브러리 파일 경로 (예: `libkiwi.so`/`libkiwi.dylib`/`kiwi.dll`). |
| `kiwi_model_dir` | `null` | Kiwi 모델 디렉터리 경로. |
| `pdfium_lib_dir` | `null` | PDFium 네이티브 라이브러리가 있는 디렉터리 경로. |

값을 채우지 않으면 어떻게 되는지:

- Kiwi 미설정(또는 `enable_morphological_analysis: false`) → 형태소 분석 없이 기본 토크나이저(bigram)만 쓴다. 한글 검색 자체는 되지만, 어미가 붙거나 불규칙 활용된 단어("짓다" ↔ "지었다" 같은 경우)를 못 찾을 수 있다.
- `pdfium_lib_dir` 미설정 → PDF는 파일명만 색인되고 본문 검색은 안 된다(파일명 검색 `-f`로는 여전히 찾을 수 있음).

두 경로 모두 채웠는데 로드에 실패하면 그때만 stderr에 경고가 뜨고, 나머지는 정상 동작한다(bigram만 사용).

## 알아둘 점

- 실행할 때마다 대상 폴더 전체를 다시 훑는다 — 색인 파일이 없기 때문이다. 같은 폴더를 자주 검색한다면 폴더가 클수록 매번 그만큼 시간이 든다.
- Kiwi를 켜면 실행마다 로드 비용(수백 MB 메모리)이 든다. 필요할 때만 켜는 걸 권장한다.

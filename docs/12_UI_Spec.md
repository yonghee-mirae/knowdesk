# UI 기획서 (Phase C)

Phase C(UI, `06_Development_Roadmap.md` C1~C5) 구현 착수 전 화면 구성·동작·키보드 흐름을 확정하기 위한 기획 문서다. 코드 변경은 없다.

F-05(검색 이력)는 MVP 범위에서 제외됐으므로(`KnowDesk_추가검토사항.md` 2026-08-21 항목) 다루지 않는다.

**대전제 (F-04):** "모든 기능은 마우스 없이 수행 가능해야 한다." 마우스 조작을 금지하는 게 아니라, 마우스 없이도 전부 가능해야 한다는 뜻이다 — 아래 각 화면에 키보드 경로를 명시한다.

---

## 가정 — 창 구성

검색창(F-04)과 프리뷰(F-03)를 **별도 창이 아니라 하나의 창 안에 배치**하는 것으로 가정한다 (Spotlight/PowerToys Run 스타일: 입력창 + 결과 리스트 + 프리뷰 패널).

근거:

- 검색창 호출 P95 300ms(PRD 4장) 목표는 "창을 미리 하나 생성해 숨겨두고 show+focus만 한다"는 방법으로 맞춘다(`11_Implementation_Plan.md`). 창이 두 개면 두 번째 창의 생성·포커스 이동 비용이 추가된다.
- 결과를 고르면서 바로 옆에서 프리뷰를 보는 것이 검색-확인 흐름에 더 맞다.

→ **확인 필요:** 이 가정이 맞는지, 혹은 프리뷰를 별도 창(또는 결과 리스트 아래 확장 패널)으로 원하는지.

## C1. 검색창 (Search Window) + 결과 리스트

```
┌───────────────────────────────────────────────────────────────────┐
│ 🔍 채권 발행                                    [내용 ▾] [파일명]  │
├────────────────────────────────┬──────────────────────────────────┤
│ 2024년_이사회_결의서.docx       │ 2024년_이사회_결의서.docx        │
│ 본문 · 정확 일치                │ D:\문서\이사회\2024\...           │
│ ...채권 발행 절차를 규정한다... │ 수정일: 2026-08-10                │
│                                  │ ──────────────────────────────── │
│ 회사채_발행_조건표.xlsx         │ ...채권 [발행] 절차를 규정한다.  │
│ 본문 · 형태소 분석              │ [이사회] 승인이 필요하다...       │
│ ...발행 조건은 시장 상황에...   │                                    │
│                                  │                                    │
│ 보안_검토_보고서.pdf            │                                    │
│ 🔒 본문 미색인(보안 문서)        │                                    │
├────────────────────────────────┴──────────────────────────────────┤
│ ↑↓ 이동  Enter 열기  Ctrl+Enter 폴더 열기  Ctrl+C 경로 복사  Esc 닫기│
└───────────────────────────────────────────────────────────────────┘
```

> **macOS 표기 — 결정됨 (2026-08-22):** 위 목업은 Windows 기준(`Ctrl`)이다. 키 처리 자체는 `Ctrl`/`Cmd` 둘 다 받아들이지만(플랫폼 무관), macOS에서는 관례상 `Cmd`를 쓰므로 화면에 표시되는 힌트 텍스트만 실행 플랫폼에 맞춰 `⌘`로 바뀐다(하단 상태바, 모드 토글 버튼 툴팁). 구현: `frontend/src/core/platform.ts`의 `MOD_KEY`.

### 동작

- 창이 열리면 입력창에 자동 포커스.
- 입력하는 대로 검색(짧은 디바운스, 예: 150ms — 정확한 값은 구현 시 조정).
- 검색 모드: **내용**(기본) / **파일명** 두 가지(F-02). 상단 토글로 전환, 키보드로도 전환 가능(`Ctrl+1`/`Ctrl+2`, macOS `Cmd+1`/`Cmd+2` — 결정됨, 2026-08-22). `Ctrl+Tab`은 채택하지 않음(숫자 단축키만 사용).
- `Ctrl+,`(macOS `Cmd+,`)로 "설정" 열기 — 트레이 메뉴의 "Settings"와 동일 동작(`settings.json`을 OS 기본 프로그램으로 염, 2026-08-24 추가). macOS/Windows 공통의 "환경설정 열기" 관례 단축키.
- 검색 문법(`05_Search_Language_v1.md`)은 입력창에 직접 타이핑 — 별도 필터 위젯 없이 `x:pdf`, `p:리서치`, `m>2026-01-01` 등을 그대로 지원(필터 접두어는 한 글자 — 직접 타이핑해야 하므로 짧게, `tier:`/`drm:`은 제거됨, 2026-08-22). MVP에서는 문법 안내를 placeholder 텍스트나 `?` 툴팁 정도로만 제공(별도 도움말 창은 범위 밖).
- 결과 리스트 각 항목: 파일명, 매치 근거 배지(**정확 일치** / **형태소 분석**, `MatchKind`), 스니펫 1줄. Meta Index 문서는 스니펫 대신 `🔒 본문 미색인(보안 문서)` 배지(`KnowDesk_추가검토사항.md` Part B-3).
- 결과 0건 시: "검색 결과가 없습니다" 안내만 표시. 오타 교정·조건 완화 재검색은 D-2 미결 항목이라 MVP 범위 밖.

### 키보드

| 키 | 동작 |
|---|---|
| `↑` `↓` | 결과 리스트 이동 |
| `Enter` | 선택 항목 파일 열기 |
| `Ctrl+Enter` (macOS `Cmd+Enter`) | 선택 항목 폴더 열기 |
| `Ctrl+C` (macOS `Cmd+C`) | 경로 복사 (결과 리스트에 포커스 있을 때만 — 입력창 포커스 중엔 텍스트 복사와 충돌하므로 제외) |
| `Esc` | 창 닫기(트레이로 숨김, 프로세스 종료 아님) |

## C2. 프리뷰 패널

C1 레이아웃의 우측 패널. 별도 화면이 아니라 결과 리스트 선택에 따라 갱신되는 패널이다.

표시 정보(F-03):

- 파일명, 경로, 수정일
- 하이라이트가 반영된 문맥 스니펫(검색 시 DB 원문에서 즉시 생성, 캐시 없음 — 이미 구현된 백엔드 동작 그대로)
- Meta Index 문서는 본문 미리보기 없이 `🔒 본문 미색인(보안 문서)` 배지 + 메타데이터만(파일명/경로/수정일/크기/확장자)

하이라이트 우선순위는 기존 구현대로: 리터럴 검색어 → Kiwi 분석 어간 → 형태소 위치(`Tokenizer::locate`). UI는 백엔드가 준 위치 정보를 그대로 렌더링한다.

> **구현 전제 조건 — 해결됨 (2026-08-22):** `SearchHit`/`SearchRow`(`core/src/search/mod.rs`, `core/src/db/search_repo.rs`)에 `extension`/`modified_at`/`index_tier`를 추가했다 — `search_filename`/`search_content` SQL이 이미 조인하던 `paths`/`documents` 컬럼을 SELECT에 포함시키기만 하면 됐다(추가 조인 없음). `filename_search_populates_metadata_fields`(`core/tests/index_search.rs`)로 검증. TASK-702/703에서 이 필드들을 그대로 쓰면 된다. (크기는 여전히 미포함 — Meta Index 미리보기에 필요하면 문서 열람 시점에 `documents.file_size`를 별도 조회하는 것으로 충분해 보이나, 확정은 아님.)

## C3. 파일/폴더 액션

- `Enter`: OS 기본 프로그램으로 파일 열기
- `Ctrl+Enter`(macOS `Cmd+Enter`): 상위 폴더를 탐색기로 열기
- `Ctrl+C`(macOS `Cmd+C`): 경로 클립보드 복사
- 마우스 클릭(더블클릭 열기, 우클릭 컨텍스트 메뉴)도 지원하되 필수 경로는 아니다 — 키보드만으로 전부 가능해야 한다는 F-04 원칙 재확인.

실패 시 안내 문구는 `KnowDesk_추가검토사항.md` E-4를 그대로 쓴다:

| 상황 | 문구 |
|---|---|
| 권한 없음 | 접근 불가 사유, 관리자 문의 안내 |
| 파일 잠김 | 다른 프로그램에서 사용 중임을 안내 |
| 원본 삭제됨 | 색인은 존재하나 파일이 없음을 안내 |
| 드라이브 오프라인 | 네트워크 연결 확인 안내, 색인 보존 여부 명시 |

## C4. 트레이 & 전역 단축키

- 트레이 아이콘 좌클릭 또는 전역 단축키(`settings.json`의 `hotkey` 필드, 기본값 `CmdOrCtrl+Alt+K` - 2026-08-24부터 설정에서 실제로 변경 가능하고 저장 즉시 재등록됨, 아래 참조)로 검색창 **토글**(닫혀 있으면 표시, 열려 있으면 숨김) — 2026-08-22부터 좌클릭도 단축키와 동일하게 토글로 통일.
- 트레이 우클릭 메뉴(2026-08-24 갱신, 영문 표기): **Settings** / **Statistics** / 구분선 / **Reset Index** / 구분선 / **Quit**. "검색창 열기"는 좌클릭이 이미 담당해서 메뉴에 없고, **"Reload"도 없다** — `settings.json`은 색인 대상 폴더와 똑같이 파일 감시 대상이라(`06_Development_Roadmap.md` TASK-706), 손으로 편집하거나 삭제해도 수동 조작 없이 자동으로 반영된다. Settings는 `settings.json` 파일 자체를 OS 기본 프로그램으로 여는 것뿐(Settings Window 대체, 위 참조 - 2026-08-24부터 폴더가 아니라 파일을 직접 염). Statistics/Reset Index는 아래 C5 참조.

  ⚠️ **수정 이력:**
  1. (2026-08-22) Reload를 처음엔 `AppHandle::restart()`(앱 전체 재시작)로 구현했다가, `npm run tauri dev`(개발 모드)에서 실제로 멈추는 문제가 있어 되돌렸다 — 개발 모드는 프론트엔드를 별도 vite 서버(`devUrl`)로 띄우는데, 앱 프로세스가 재시작으로 죽는 순간 `tauri dev`의 오케스트레이터가 dev 세션이 끝났다고 판단해 그 vite 서버와 터미널 세션까지 같이 정리해버린다. 대신 색인 워커 스레드에 컨트롤 채널(`IndexCommand::Reload`)을 둬서 `settings.json`을 다시 읽고 `watched_folders`만 그 스레드 안에서 적용하도록 바꿨다.
  2. (2026-08-23) 그 컨트롤 채널·"Reload" 메뉴 항목 자체를 없애고, 이미 있는 파일 감시 기능을 `settings.json`에도 그대로 적용했다 — `run_index_worker`가 색인 대상 폴더용 `FileWatcher`와 별개로 `settings.json`이 있는 폴더도 감시한다. 수정 이벤트가 오면 다시 읽어서 `watched_folders` 변경분을 적용(`core/src/index/watcher.rs`의 `FileWatcher::watch`/`unwatch`로 이미 떠 있는 watcher에 루트를 즉석으로 추가/제거)하고, 삭제 이벤트가 오면(파일이 실제로 없어졌는지 확인 후) 기본값으로 재생성한다. "수동으로 누르는 Reload"가 있을 필요 자체가 없어졌다.
- **P95 300ms 달성 방법**(`11_Implementation_Plan.md`, 재확인): 창을 앱 시작 시 미리 생성해 숨겨두고, 단축키 입력 시 show+focus만 수행한다. 콜드 스타트로는 300ms를 맞출 수 없다.
- 검색창이 이미 열려 있을 때 단축키를 다시 누르면? → **단순 토글이 아니라 3단계 상태 (2026-08-24 수정)**: (1) 보이고 + 포커스도 있음 → 숨김, (2) 보이지만 포커스가 없음(다른 창을 눌러서 포커스만 옮겨간 경우) → 숨기지 않고 포커스만 다시 가져옴, (3) 숨겨진 상태 → 보이고 포커스. 좌클릭도 동일한 3단계 로직(`toggle_search_window`) 공유.
- **트레이 전용, 태스크바/Dock 비노출 (2026-08-24 확정):** 창을 보여줄 때도 태스크바(Windows/Linux)나 Dock(macOS)에 실행 상태로 뜨지 않는다 - macOS는 앱 전체의 activation policy를 `Accessory`로(Dock 아이콘·Cmd+Tab 전환창 제외), Windows/Linux는 검색창의 `skipTaskbar: true`로 처리.
- **중복 실행 방지 (2026-08-24 확정):** 이미 실행 중일 때 다시 실행하면 새 프로세스는 안 뜨고, 기존 프로세스의 검색창을 보여주고 포커스만 준다(`tauri-plugin-single-instance`) - 좌클릭/단축키의 토글과 달리 이미 열려 있어도 숨기지 않는다.

## C5. 설정 & 진단

### 설정 화면 (Settings Window, TASK-704) → 폐기, "설정 파일 열기"로 대체

⚠️ **결정 (2026-08-22):** 아래 mockup처럼 Settings Window(폴더 추가/제거 UI, 네이티브 다이얼로그 포함)를 실제로 구현했다가, 사용자 지시로 걷어내고 훨씬 단순한 방식으로 바꿨다 — 트레이 메뉴의 "Settings"를 누르면 `settings.json`이 들어있는 폴더를 OS 파일 관리자로 열어줄 뿐이고(`src-tauri`의 `open_settings_folder`), 그 파일을 텍스트 에디터로 직접 편집하는 게 UI 전체다. 앱 시작 시 그 파일이 없으면 `Config::default()`로 기본값 파일을 만들어둔다(`core::config::Config::save`). 아래 mockup은 실제로 구현되지 않은 과거 설계로만 남겨둔다.

⚠️ **결정 (2026-08-24):** "Settings"가 폴더를 여는 대신 **`settings.json` 파일 자체를 OS 기본 프로그램(텍스트 에디터)으로 바로 연다** — `open_settings_folder` → `open_settings_file`로 함수명도 변경(`app.opener().open_path()`에 파일 경로를 직접 넘김, `parent()`로 폴더를 구하던 중간 단계 제거). 폴더가 아니라 파일을 직접 열어주는 쪽이 한 클릭 덜 든다는 판단.

⚠️ **결정 (2026-08-23):** 검색바에 있던 설정 버튼(톱니바퀴)·테마 전환 버튼(해/달 아이콘)을 둘 다 없앴다. 설정은 트레이 메뉴로 충분하고(위 참조), 테마는 버튼으로 토글하는 게 아니라 `settings.json`의 `theme` 필드(`dark`/`light`/`system`, `core::config::Theme`, 기본값 `system`)로 지정하는 설정값이 됐다 — 페이지 로드 시 한 번, 그리고 검색창이 포커스될 때마다(트레이/단축키로 다시 열릴 때) 다시 읽어서 적용한다(`frontend/src/core/theme.ts`의 `loadAndApplyTheme`). 창을 한 번 만들어두고 계속 보여주기만 하는 구조라(P95 300ms) 이렇게 "다시 포커스될 때 재확인"하는 방식이 아니면 손으로 고친 테마가 반영될 시점이 없다.

버그 하나가 이 결정과 얽혀 있다: 걷어내기 전 버전에서 "폴더 추가" 클릭 시 앱이 멈추는 실제 버그가 있었다 — `tauri_plugin_dialog`의 `blocking_pick_folder()`를 동기(non-async) 커맨드에서 호출해서 생긴 메인 스레드 데드락. 기능 자체를 없애면서 그 버그도 같이 사라졌다.

## 열린 질문 (확인 후 수정)

1. 검색창+프리뷰가 하나의 창인가, 별도인가 — 이 문서는 "하나의 창"으로 가정.
2. **폴더 열기 단축키 조합 — 결정됨 (2026-08-22):** `Ctrl+Enter`(macOS `Cmd+Enter`)로 구현됨. 키 처리는 `e.ctrlKey || e.metaKey`로 플랫폼 무관하게 둘 다 받아들이고, 화면 힌트만 실행 플랫폼에 맞춰 표시.
3. 이미 열려 있는 검색창에서 단축키 재입력 시 토글(닫힘) 여부 — 토글로 가정.
4. **검색 모드(내용/파일명) 전환 키보드 단축키 — 결정됨 (2026-08-22):** `Ctrl+1`/`Ctrl+2`(macOS `Cmd+1`/`Cmd+2`)로 구현됨. `Ctrl+Tab`은 채택하지 않음.
5. `SearchHit`/`SearchRow`에 수정일·확장자·`index_tier`가 없어 Preview/결과 리스트 요구사항을 충족하려면 백엔드 확장이 선행돼야 함 — TASK-702/703에 포함할지, 별도 태스크로 뺄지.
6. 색인 스로틀링 파라미터를 설정 화면에 노출할지 — 비노출로 가정.
7. 색인 미완료 상태에서 검색을 막을지 여부 — 막지 않고 진행률만 표시하는 것으로 가정.
8. **창 크기는 고정 — 결정됨 (2026-08-22):** 결과 개수·프리뷰 유무·뷰포트 폭에 따라 창 크기가 달라지면 안 된다. P95 300ms 달성 방법이 "창을 미리 생성해 숨겨두고 show+focus만 한다"(위 가정, `11_Implementation_Plan.md`)인데, 네이티브 창 리사이즈는 그 자체로 OS 레벨 오버헤드가 있어 이 목표와 충돌한다. 결과 리스트는 창 크기 변경 없이 내부 스크롤로 처리한다(브라우저 프로토타입에서 뷰포트 폭에 따라 프리뷰 패널을 숨기던 반응형 분기를 제거하고 고정 폭으로 수정 — Tauri 창은 우리가 크기를 직접 지정하므로 웹페이지식 반응형이 애초에 불필요). Tauri 창 설정(`resizable`/고정 `width`·`height`)은 TASK-701에서 명시적으로 잠글 것.
